   236→## Phase 6: Incremental agentic planning + per-job results pages + EMPIAR-10017
   237→
   238→### Architectural change: incremental agent (one job at a time)
   239→- **Before**: the LLM planned the ENTIRE workflow upfront (13-job DAG), then the
   240→  engine executed them one-by-one. This was not truly agentic — the agent never
   241→  looked at intermediate results to decide the next step.
   242→- **After**: `chatReply()` now plans ONLY the first job (import). After each job
   243→  completes, `planNextJob()` calls the LLM with the completed job's output + full
   244→  history, and the LLM decides the SINGLE next job (or declares done). This makes
   245→  the agent truly adaptive — e.g. after class2d, it looks at the class distribution
   246→  and decides whether to retry with more classes or proceed to 3D.
   247→
   248→### Cycle detection
   249→- If the LLM tries to create the same task type >2 times (e.g. re-running class2d
   250→  after class3d is skipped), the agent declares done to prevent infinite loops.
   251→
   252→### CPU-skip continuation
   253→- After a CPU-impractical task (initialmodel, class3d, refine3d) is auto-skipped,
   254→  `planNextJob` is now triggered so the agent can decide the next CPU-feasible step
   255→  (e.g. maskcreate + postprocess using reference.mrc). Previously the pipeline
   256→  would stall after a skip.
   257→
   258→### Per-job results pages (UI refactor)
   259→- **Before**: all visualizations were crammed into one scrolling "Visualizations"
   260→  tab, plus a separate "Results" tab and "Job inspector" tab.
   261→- **After**: clicking a job card in the workflow DAG navigates to a dedicated
   262→  **per-job results page** showing: parameters, output summary, output files
   263→  (with download), live log, and the visualizations specific to THAT job
   264→  (class averages + angular heatmap for class2d; FSC + Guinier + 3D volume for
   265→  postprocess; slice viewer + 3D volume for maskcreate). A "Workflow" back button
   266→  returns to the DAG.

   370→## Phase 9: Critical binary PNG fix + class2d images working
   371→
   372→### ROOT CAUSE FOUND: PNG binary corruption
   373→The slice API (`/api/slice`) and thumbnail API (`/api/files?thumb=1`) were
   374→corrupting PNG binary data. `execFile` was returning stdout as a string, and
   375→when `Buffer.from(stdout)` was called, non-UTF-8 bytes (like `\x89` — the PNG
   376→magic number) were replaced with the UTF-8 replacement character `\xef\xbf\xbd`.
   377→This made every PNG invalid — the browser couldn't render them, so all MRC-slice
   378→images (class averages, micrograph thumbnails, map slices) showed "No image".
   379→
   380→**Fix**: Set `encoding: "buffer"` in the `execFile` options so stdout is
   381→returned as a Buffer directly, bypassing the string conversion entirely.

   762→### Architecture
   763→Created a **VLM-based quality verification system** that runs after each
   764→supported task completes:
   765→
   766→```
   767→job done → VLM inspects result images → pass? → planNextJob
   768→                                     → fail? → create retry job with adjusted params
   769→                                              (max 3 retries, then proceed anyway)
   770→```
   771→
   772→### New files
   773→
   774→**mini-services/relion-runner/render_preview.py**
   775→- Python script that renders result images for VLM inspection
   776→- Modes: `picking` (micrograph + green circles), `classgrid` (class averages
   777→  grid), `particles` (particle thumbnails grid), `slice` (3D volume slice)
   778→- All outputs downsized to 768px max (VLM-friendly)
   779→
   780→**src/lib/agent/verifier.ts**
   781→- `verifyJobQuality(projectId, job)` — dispatches to per-task verifiers
   782→- Per-task verifiers:
   783→  - `verifyAutopick`: renders picking overlay, asks VLM if circles are on
   784→    actual particles or noise
   785→  - `verifyExtract`: renders particle thumbnails grid, asks VLM if boxes
   786→    show clear protein density
   787→  - `verifyClass2D`: renders class averages grid, asks VLM if classes show
   788→    clear secondary structure
   789→  - `verify3DRefinement`: renders middle z-slice of 3D map, asks VLM if
   790→    density is well-defined
   791→  - `verifyCtffind`: heuristic check on avg CTF resolution
   792→- `adjustParamsForRetry(taskType, params, retryCount, verification)` —
   793→  combines VLM-suggested params with retry-strategy-specific defaults
   794→- `clampSuggestedParam(key, value)` — clamps VLM-suggested values to safe
   795→  ranges (prevents nonsensical values like particle_diameter=0)
   796→- Uses `zai.chat.completions.createVision()` with base64-encoded PNGs
   797→- Fails open (assumes passed) if VLM call fails — pipeline doesn't stall
   798→
   799→### Engine integration (engine.ts)
   800→
   801→After a job completes successfully:
   802→1. If task type is verifiable (autopick, extract, class2d, class3d, refine3d,
   803→   initialmodel, ctffind), call `verifyJobQuality()`
   804→2. Record result as a `Decision` (kind="verify", action="pass"/"fail")
   805→3. Post a chat message with score emoji (🟢/🟡/🔴) + reasoning
   806→4. If failed AND retryCount < 3:
   807→   - Compute adjusted params (VLM suggestions + retry strategy)
   808→   - Create a new queued retry job with adjusted params
   809→   - Strip "(retry N)" from alias to avoid nesting
   810→   - Don't add to finishedNow (retry will run first)
   811→5. If passed OR max retries reached:
   812→   - Add to finishedNow → triggers planNextJob
   813→
   814→### Retry strategies (per task type)
   815→
   816→- **autopick**: retry 1 = switch method (topaz↔LoG); retry 2 = adjust
   817→  diameter ±25%; retry 3 = adjust threshold
   818→- **class2d**: retry 1 = +5 iterations; retry 2 = ×2 tau_fudge;
   819→  retry 3 = fewer classes
   820→- **class3d/refine3d**: +2 iterations each retry
   821→- **extract**: retry 1 = +16px box size; retry 2 = +20% diameter
   822→

   828→- **"next-job-planned" decision**: recorded after planNextJob runs, so the
   829→  idle-tick fallback knows not to re-plan for the same completed job.
   830→- **Alias nesting fix**: retry jobs strip existing "(retry N)" suffix from

  1017→### User insight (correct)

  1026→- Line: `n_iter = min(int(p.get("iter_nr_iter", 5)), 5)`
  1027→- 5 iterations is far too few for real data to converge
  1028→- RELION typically needs 15-25 iterations for class averages to sharpen
  1029→- This was the PRIMARY reason class2d produced "blurry, featureless blobs"

  1032→- The old code hard-coded: `mic = parts[3]` (column 4 = micrograph name)
  1033→- But the autopick.star has columns: _rlnCoordinateX #1, _rlnCoordinateY #2,
  1034→  _rlnMicrographName #3, _rlnOpticsGroup #4

  1036→- The micrograph name is at parts[2] (index 2)
  1037→- This caused ALL particles to be skipped with "SKIP 1 (not found)"
  1038→- The extract produced 0 particles → class2d had nothing to classify

  1041→- EMPIAR-10017 ships with expert manual picks (particles.star)
  1042→- These are far better than LoG on real data

  1436→  process survives even when the parent bash exits
